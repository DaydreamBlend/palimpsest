# Qwen3.5-9B NVFP4 마지막 비교 결과

2026-09-10. 사용자가 지정한 **Qwen3.5-9B의 NVFP4 양자화 버전**을 내려받아 같은 스크립트 초안으로 시험했다. 정상 초안의 문맥 구성은 기존 9B Q8_0와 같았지만, 잘못된 Figure 캡션 연결을 넣은 대조에서는 오류를 놓쳤다. 이번 결과로 NVFP4의 오류 검출이 Q8_0와 동등하다고 결론내릴 수 없다.

## 결과 비교

Test_Paper.pdf의 동일 source I·스크립트 초안·정책·검토 후보·출력 스키마를 사용했다. 20개 이슈를 7개 입력으로 나눠 세 번 반복했다. 모델은 이 후보에 필요한 83개 고유 I의 텍스트·종류·페이지 정보를 받았고, 스크립트가 229개 I 전체를 보존했다. 정식 21회 외에 실행 확인 1회와 같은 두 오류 대조 1회를 별도로 수행했다.

NVFP4의 세 반복 모두 Q8_0 및 4B와 그룹 소속·역할·Figure 참조·Figure companion이 같다. 원문을 다시 써서 합친 것이 아니라 읽기용 그룹을 만든 결과다. 스크립트 초안에서 매회 달라진 것은 Abstract I57을 metadata에서 별도로 분리한 한 건뿐이다. 전체 구성은 이전 [문맥 그룹 상세](../t03-script-context-review/CONTEXT_GROUPS.md)와 같다.

정식 판단 60개도 두 모델과 모두 같았다. 그러나 Q8_0와 근거 ID 집합·순서가 같은 것은 33/60개, 이유 코드가 같은 것은 42/60개다. 그룹이 같다는 사실이 전체 검토 기록이나 근거의 충분성이 같다는 뜻은 아니다.

## 마지막 오류 대조

두 오류는 이전 9B/4B 대조와 동일하며, 기대 답안은 모델에 제공하지 않았다.

1. 실제 한 문장의 source 75와 104를 페이지 경계에서 잘못 나눈 제안: NVFP4가 `merge_previous`를 반환해 감지했다.
2. Figure 5의 시작 캡션 152에 Figure 6의 계속 캡션 189를 잘못 연결한 제안: NVFP4가 **`keep`**을 반환했다. 기대 판단은 `needs_context`다.

두 번째 응답은 Figure 5의 올바른 쌍 152/158과 Figure 6의 올바른 쌍 183/189를 모두 근거로 선택하면서도 잘못된 제안 152/189를 유지했다. 근거 목록에 올바른 source가 있다고 제안의 오류가 고쳐진 것은 아니다. [실제 대조 응답](controls/runs/sensitivity/repeat-1/decisions.json)

이 대조는 **NVFP4 1/2, Q8_0 2/2, 4B 1/2**다. 한 번 실행한 두 사례를 일반적인 정확도 50% 또는 100%로 표현하지 않는다. 정식 21회와 합산하지 않았으며 실패한 응답을 재시도하거나 prompt를 조정하지 않았다.

## 근거 선택과 평가 범위

사후 검토에서는 NVFP4가 Figure 1–3의 판단에서 실제 전체 캡션 I90/I103/I128을 근거 ID로 선택하지 않은 점도 확인했다. 모델 입력에는 해당 캡션이 있었으나 일부 반환 근거는 짧은 패널 글자뿐이었다. 여섯 Figure를 세 번 확인한 18건 중 실제 캡션 source ID를 직접 인용한 것은 NVFP4 9/18, 기존 Q8_0와 4B는 각각 18/18이었다. 이는 이번 출력을 읽고 추가한 정성 진단이며 기존 정식 점수의 기준을 바꾸지 않았다. 원문 caption I가 삭제되거나 입력에서 누락된 사건과도 구분한다. [독립 검토](FINDINGS.md)

주 평가 대상 103개 I의 pairwise F1은 세 모델 모두 0.96635로 같다. 사전 probe는 16/18이며 남은 두 항목은 Figure 1의 실제 두 소절을 한 묶음에 넣는 수동 참조의 선호와 다르기 때문이다. 스크립트 초안도 primary F1이 같았으므로 모델이 문맥 구성을 전반적으로 개선했다고 과장하지 않는다. 관찰된 개선은 Abstract 역할 분리다.

실행 확인용 smoke는 구조상 유효했지만 NVFP4가 `keep/study_overview`를 반환해 기존 모델의 `needs_context`와 달랐다. 이 입력은 처음부터 형식·전송 확인을 위한 것으로 정식 품질 점수에 포함하지 않았다.

## 사용한 파일과 실행 조건

공개 커뮤니티 변환본 [FreedomAISVR/Qwen3.5-9B-NVFP4-GGUF](https://huggingface.co/FreedomAISVR/Qwen3.5-9B-NVFP4-GGUF)의 revision `3db49b5e08fb84a2ead8d6407f38f6638c79d08a`를 사용했다. 파일은 `qwen3.5-9b-nvfp4.gguf`, 5,313,356,640 bytes, SHA-256 `0db703913b6a1b057d423e9815095e9dc16499596a986446918314a48c4d9bad`다. 다운로드 후 전체 해시와 실제 GGUF 구조를 검증했다.

실제 tensor 형식은 NVFP4 249개, Q6_K 출력층 1개, F32 177개다. Q8 파일과 427개 tensor 이름·shape, 총 8,953,803,264개 파라미터가 같다. 모든 가중치와 모든 연산이 FP4인 구성이라고 표시하지 않는다. [실제 파일 비교](runtime/gguf-comparison.json)

기존 llama.cpp b10380, 고정 Docker 이미지, RTX 5080을 재사용했다. Context 32,768, thinking budget 설정 2,048, output limit 4,096, temperature 0, seed 42, cache off, text-only 조건을 유지했다. 실제 reasoning 토큰을 따로 계수하거나 GPU kernel profiling을 한 것은 아니다. 고정 소스는 SM120 NVFP4 MMQ를 지원하지만 단일 토큰 decode는 다른 MMVQ 경로를 사용할 수 있다. [런타임 지원 근거](runtime/runtime-support.json)

커뮤니티 변환본의 정확한 원본 revision과 변환 도구 commit은 확인되지 않았다. Vocab·merge·token type·EOS는 같지만 padding ID, BOS 설정의 명시 여부, template 일부 및 F32 값 6개가 다르다. F32 차이는 각 1 ULP다. 실제 고정 요청은 단일 사용자 텍스트·`enable_thinking=true`·도구 호출 없음이어서 template의 변경 분기가 적용되지 않는다는 정적 검토를 기록했다. Jinja 렌더링을 실행해 비교한 것으로 표시하지 않는다. 따라서 결과 차이를 순수하게 양자화 한 변수의 효과라고 단정하지 않는다.

정식 호출 시간 합계는 NVFP4 363.65초, Q8_0 1,482.78초, 4B 260.55초다. NVFP4의 호출별 중앙값은 17.16초다. 표의 1회분 시간은 일곱 입력의 처리 시간을 더한 값의 중앙값이며 모델 다운로드·로딩·실험 사이의 대기·smoke/control을 제외한다. 시작 시 GPU 부하도 각각 25%, 91%, 10%로 달랐으므로 통제된 속도 벤치마크로 해석하지 않는다.

## 완료 범위

이 시험에서 NVFP4는 더 작은 파일로 같은 정상 문맥 구성을 재현했다. 그러나 Q8_0가 감지한 잘못된 캡션 연결을 놓쳤고 일부 근거 선택도 약했다. **검증 역할에서 Q8_0를 동등하게 대체한다고 판단할 근거는 부족하다.** `needs_context`가 나온 경우만 큰 모델로 넘겨도 `keep`으로 놓친 이번 오류는 걸러지지 않는다.

이번 사용자가 요청한 마지막 모델 실험은 완료했다. 제품 기본값·원본 D/I·기존 실험·DB·canonical·T03/T04 acceptance 상태는 변경하지 않았다. 한 논문과 고정 후보의 텍스트 검토 결과이며 파서/OCR fidelity, 이미지 이해, 다른 논문 일반화 또는 실제 K 생성 품질의 검증 결과가 아니다.

이전 HF CLI 이미지로 다운로드했고 새 이미지·패키지·vision projector를 추가하지 않았다. 다운로드용 임시 컨테이너 1개는 자동 제거됐고, 실행용 4개는 로그를 보존한 뒤 제거했다. 검증 완료 NVFP4 파일과 전체 실험 산출물은 남겼다. 원본·Docker 전후 감사, 정확한 명령과 CPU/문서 검사 결과는 [실행 기록](../../progress/T03_script_context_review_nvfp4_execplan.md)에, 수치와 입력/출력 해시는 [독립 평가](EVALUATION.md) 및 [metrics.json](metrics.json)에 기록한다.
