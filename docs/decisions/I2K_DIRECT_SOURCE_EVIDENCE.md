# I2K의 근거 공백: D2I 재실행 금지와 직접 D 근거

**직접 D→K 허용 철회 — 2026-09-13:** 아래는 과거 결정 기록이다. 최신 사용자는 이 경로를 규약에 없는 D2K로 거부했다. 현재는 [실제 I 근거만 허용하며 D2I 오류를 보고](I2K_INFORMATION_ERRORS.md)한다. I가 부족하면 관련 K를 보류하고 사용자에게 알리며 원문을 근거로 K를 우회 생성하지 않는다. 아래 직접 grounding 구현/검증 요구를 현재 승인으로 적용하지 않는다.

2026-09-11 최신 정정: [I2K 원문 정리·새 결론은 K2K](I2K_SOURCE_ONLY_K2K_INFERENCE.md)를 따른다. [다중 Data I2K](MULTI_SOURCE_I2K.md)의 원본 요청은 각 근거 I가 실제로 속한 D에 결속한다. 여러 문서를 사용하는 실행에서도 하나의 대표 Data나 페이지 번호만으로 요청 원본을 선택하지 않는다. 직접 D 예외도 원문에 실제 명시된 내용을 검증하는 경로이며 I2K의 새로운 결론·추측 생성을 허용하지 않는다.

2026-09-11 최신 사용자 지시. [전체 D↔I 대응과 LLM 선택](FULL_SOURCE_LLM_SELECTION.md), [I 우선 원본 추가 조회](I2K_I_FIRST_SOURCE_ON_DEMAND.md)의 후속이다. 이전의 “근거 공백을 D2I 보완·새 source snapshot으로 처리” 지침을 이 범위에서 대체한다. 별도 사용자 승인을 다시 요구하는 제안이 아니다.

## 승인된 동작

D2I는 하나의 등록된 D를 한 번 충실하게 처리하여 어느 원문 구간도 I를 통해 찾을 수 있게 하는 것을 목표로 한다. I2K의 필요 근거 부족, OCR 불일치, 모델의 추가 조회 요청을 이유로 D2I 재파싱·재청킹·regroup·source-pages 실행이나 새 I 생성을 자동 호출하지 않는다. 과거 D/I/source 실행/ID/hash/profile/Revision은 변경하지 않는다. 미완료 D2I 실행의 기존 복구 규약과 별도 사용자가 요청한 유지보수는 I2K의 자동 재실행 경로가 아니다.

I2K는 선택한 하나의 source execution의 전체 I를 검토한다. 다른 이미 보존된 I나 Image I에 필요한 근거가 있으면 그 실제 I를 인용한다. 현재 창에 없는 I의 추가 조회, 파싱 텍스트 대신 이미 보존된 Image I를 읽는 것, 실제 I에 없는 원문 내용을 처음 확인하는 것은 구분한다.

I에서 충분한 근거를 확보하지 못하면 동일 `data_id`에 연결된 등록 원본 D를 조회한다. PDF는 등록된 원본 bytes의 SHA와 실제 전달을 확인하고, 원본에서 해당 내용을 읽어 독립 검증한 뒤 K를 생성하거나 기존 K에 근거를 추가한다. I가 담지 않은 내용은 **직접 D 근거**로 남긴다. 관련 I가 있으면 탐색의 출발점으로 연결할 수 있지만 이를 그 주장을 뒷받침하는 I로 위장하지 않는다. D에도 근거가 없거나 실제 전달·읽기·검증이 불가능하면 관련 후보는 미해결이다.

이것은 I2K 안의 예외 근거 경로다. 전체 I 검토를 생략하는 기본 D2K 경로나 D2I를 반복 보정하는 루프로 바꾸지 않는다. 원본 파일을 이미지로 열어 읽는 provider라면 원본 PDF bytes의 준비·전달과 파생 페이지 이미지의 실제 전달을 구별하며, 아직 전달하지 않은 원본을 전달했다고 기록하지 않는다.

## 기록과 검증

다음 항목을 해당 I2K 실행과 KCompilationRecord에 결속해 영속 보존해야 한다. 아래는 승인된 데이터 요구이며 현재 DB에 모두 설치되었다는 뜻은 아니다.

- 직접 근거의 `data_id`/원본 SHA와 위치: PDF의 원본 page/bbox 및 좌표계, 텍스트의 원문 byte/line 범위 등 형식에 맞는 locator. 원본 인용/실제 이미지 근거와 해당 artifact SHA를 함께 남긴다.
- 선택된 source execution/profile/parse manifest, 조회한 I와 범위, 원본 요청 질문·이유, 실제 model 전달 receipt, 확인한 위치와 Validator 결과. I가 없으면 근거 I FK를 임의로 만들지 않는다.
- 원문 근거와 연결된 정확 KNodeRevision 및 origin Record. 의미가 같으면 grounding만 추가하고, 의미가 실질적으로 달라질 때만 기존 materiality 규칙에 따라 Revision을 만든다.
- 근거 공백 또는 불일치의 오류/품질 이력. 원본을 확인하기 전에는 누락 **의심**이며, 확인 후 원문과 I를 대조해 누락/전사 불일치/조회 문제 등을 구별한다. 단순한 추가 문맥 요청을 확인된 D2I 누락으로 단정하지 않는다.
- K 근거 검증 상태와 source 품질 문제 상태를 분리한다. 원본으로 K를 검증할 수 있어도 기존 I의 누락이 사라진 것은 아니다. 예외 처리와 미해결 품질 이력은 계속 조회 가능해야 한다. 실패·미제공·미검증을 성공으로 표시하지 않는다.

canonical K/직접 grounding, 판정 Record, 예외 근거 연결, 후속 outbox는 기존 atomic 반영 규약을 따른다. 외부 전송 권한, general/source 중복 규칙, R07/R08와 역사 불변성은 유지한다. 원본 파일 제공 자체가 지식의 진실성 승인은 아니다.

## Wiki 조회에서의 의미

기본 답변 경로는 Query → 관련 K의 정확 Revision → 실제 grounding I → 같은 D의 방법·조건·관련 I → 원문 위치다. 추론 K는 K2KRecord의 정확 전제 KRevision/EffectiveEdgeRef를 거쳐 I/D까지 역추적하며 결론 자체의 가짜 direct I 근거를 만들지 않는다. 직접 D 근거로 생성된 K는 Query → K Revision → 직접 D grounding을 따르며 예외 표시를 유지한다. 답변의 각 주장에 실제 사용한 I/D 인용을 붙이고 사용한 K/Edge Revision·retrieval/input snapshot을 기록한다.

여러 논문의 유사 실험은 출처·실험 조건을 유지한다. 동일 용어가 있다고 서로 다른 종/코호트/제작과 투여 조건을 합치지 않는다. 문헌의 방법은 저자의 보고이며 사용자가 실제로 수행했다는 기록이 아니다. “내가 어떻게 만들었지?”를 개인 수행 이력으로 답하려면 실험 노트 등 그 행위를 뒷받침하는 D와 행위자·시점·실험 식별 근거가 필요하다.

K는 중요한 내용을 선택한 결과이므로 전체 제작 절차가 K의 짧은 statement에 들어 있다고 가정하지 않는다. 관련 K로 출처를 찾은 후 그 I의 충분한 문맥과 같은 D의 관련 I를 읽는다. K에 선택되지 않은 중요한 질문 근거를 발견하면 I 직접 사용과 검증된 K 기반 답변을 구별해 표시한다. 이 문서는 검색 index나 K2W 구현 완료를 의미하지 않는다.

## 실제 상태와 다음 검증

현재 I2K 코드에는 D2I 재호출 경로가 없다. 원본 요청은 `k_source_requests`에 보존되지만 현재 Codex adapter는 native PDF 전달을 지원하지 않아 관련 후보를 보류한다. `knowledge_node_groundings`는 I 기반이며 직접 D grounding은 미구현이다. K/Edge Revision과 K → I → D 조회 기반은 저장·실행되어 있으나 BGE-M3 검색 adapter/index, 자연어 답변 및 K2W 저장은 후속 작업이다.

직접 D 근거 경로를 구현할 때는 기존 완료 migration을 고치지 않고 추가한다. 최소 검증은 (1) 누락/전사 충돌 상황에서도 D2I 호출 및 I 변경 0, (2) 실제 원본 hash·전달·인용 결속, (3) 원본 미제공/변조/다른 D/무근거 후보 거부, (4) 검증된 직접 D 근거와 오류 이력의 atomic 저장 및 replay, (5) 같은 의미의 근거 추가에 Revision 증가 0, (6) 예외 K의 답변 역추적과 오류 표시다. 이번 정책/조회 점검을 이 후속 구현의 통과로 보고하지 않는다.
