# Realm R과 I2K의 기본 범위

**2026-09-14 후속 요구:** 사용자는 D를 처음 등록할 때 Realm을 지정하고, 잘못 분류한 경우에는 수정할 수 있어야 한다고 요청했다. 이는 다음 구현의 요구이며 현재 import의 필수 필드로 이미 적용됐다는 뜻은 아니다. K2K 이후 분류 정정의 영향, 생성 당시 scope와 현재 소속 구분, 진행 중 작업 처리 정책은 [최신 남은 구현](../../progress/IMPLEMENTATION_BACKLOG_2026_09_14.md)에 정리했다. 아래의 I2K-only 실행 제한을 K2K 전면 격리가 이미 구현됐다는 의미로 확대하지 않는다.

2026-09-14 사용자 요청 및 명시적 선택: 비슷한 Data를 Realm R로 모으고 코드베이스와 논문의 I가 I2K에서 우연히 함께 사용되는 것을 줄인다. 사용자는 **기본 분리·명시적 교차 허용**을 선택했다.

Realm은 자료를 묶는 project/topic 공간이며 D/I/K 사이의 새 변환 단계가 아니다. MIME/file type과 구분한다. 코드 프로젝트의 Realm에 관련 설계 Markdown이나 참고 논문이 들어갈 수 있다. 하나의 Electron 앱에서 모든 자료를 볼 수 있어야 한다는 요청도 유지한다.

승인된 처리 규칙:

1. 새 I2K 실행은 같은 Realm의 자료를 기본 입력 범위로 사용한다.
2. 다른 Realm의 자료는 사용자가 명시적으로 선택한 경우에만 함께 사용할 수 있다. Realm을 자동 추천에만 쓰는 soft priority는 선택하지 않았다.
3. 실행은 실제 선택된 Realm·자료 범위와 명시적 교차 선택 여부를 보존해야 한다. 준비 이후 범위가 바뀌면 원래 승인을 다른 입력에 적용하지 않는다.
4. Realm 도입이나 자료 재분류는 기존 D content hash, I, K identity/Revision, source provenance, 과거 실행을 다시 쓰는 이유가 아니다. Realm은 원문 복제·D2I 재실행 수단이 아니다.
5. Realm은 provider 전송 권한이나 사용자 결정 권한을 자동으로 부여하지 않는다. 이번 승인은 I2K의 기본 자료 범위이며 다른 변환의 전면 교차 금지나 접근 제어 정책으로 조용히 확대하지 않는다.

구현 시 확정할 사항: 물리 Realm 저장과 membership 이력, 여러 기존 저장소의 trusted source references, 기존 미분류 자료의 표시, 단일 Data의 다중 Realm 소속과 전역 K 재사용의 경계. 새로운 저장소 통합을 위해 기존 DB를 삭제하거나 source를 재등록하지 않는다. 사용자가 승인한 기본 범위는 구현 편의를 이유로 soft priority로 바꾸지 않는다.

진행 순서는 현재 EffectiveEdge K2K 마무리 후, 통합 Electron UI와 Realm metadata/범위 연결이다. 실제 구현·마이그레이션 완료 기록은 후속 실행 계획에서 구분한다.
