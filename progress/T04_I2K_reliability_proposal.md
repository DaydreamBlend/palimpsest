# I2K 원문 충실성과 검증 개선안

2026-09-11. 사용자는 지난 실험의 문제를 해결할 방법을 검토하도록 요청했고, 이어 **K가 반드시 통합될 필요는 없다**고 명확히 했다. 이 문서는 설계 검토 결과다. 아래 구현 순서와 새 검증 필드들은 제안이며 적용·성능 검증·DB migration 승인을 뜻하지 않는다. 과거 실험 결과와 IDs/Revision/출력은 수정하지 않았다.

## 성공 기준의 정정

다중 Data의 I를 한 K에 연결하는 기능은 사용할 수 있지만 산출 의무가 아니다. 여러 Data의 K가 각자 정확한 원문·실험 조건을 유지하면 정상이다. 기존의 의미 동일성 검증에 따른 reuse 원칙은 유지하며, 주제 유사성이나 통합 개수 목표로 서로 다른 실험을 합치지 않는다. 따라서 이전 실험의 multi-Data 근거 K 0개는 이제 실패 기준이 아니다. 원문 범위 확대, 불충분한 인용 승인, 기존 오류 K의 미정정은 여전히 해결 대상이다.

## 관찰된 사실과 가설

- Dejani의 한 후보는 서로 다른 처치의 결과를 넓혀 묶었다. 최초 Validator는 승인하고 후속 Validator는 기각했다. 원문보다 강한 주장이 저장되는 것을 현재 boolean 검증만으로 차단하지 못했다.
- Clarke의 DC 후보는 유효한 continuation block ID를 인용했지만 핵심 방향을 서술한 앞 블록을 빠뜨렸다. 원문 전체 I에는 그 내용이 존재한다. 이는 D2I 누락이 아니라 선택된 인용의 부족이다.
- 후속 Validator의 여러 reuse 이유가 기존 K와 같다는 설명으로 끝났다. 기존 K와의 비교와 원문 충분성 검사를 함께 수행하는 것이 오류를 유지시키는 경로일 수 있다. 이를 인과적으로 입증한 실험은 아직 없으므로 분리 전후를 비교해야 한다.
- 대량 입력이나 같은 모델 사용이 오류의 원인이라는 결론은 내리지 않는다. 우선 기존 모델을 유지해 검증 계약의 변경 효과를 측정한다.

## 권고하는 순서

원문 I → 원문에 명시된 후보 생성 → 후보의 각 중요한 내용과 근거 대조 → 동일 의미 여부 비교 → 새 K 또는 기존 Revision에 검증된 근거 반영 → N2E.

중요한 내용의 선택은 LLM이 담당한다. 스크립트는 refs/범위/전체 I 검토 기록/필수 판정의 완전함과 원자 저장을 검사한다. 전체 I가 I2K 루프를 통과한다는 계약은 유지하며, 하나의 호출에 모든 논문을 넣는 것 자체를 성공 조건으로 삼지 않는다.

### 1. 원문 지지와 동일 의미 판정을 분리한다

근거 Validator는 후보의 statement·구조화 내용·원문 인용과 필요한 I 문맥을 받는다. 기존 K의 승인 여부, Generator의 정당화 문구, 기존 K catalog를 근거로 삼지 않도록 입력을 분리한다. 그 결과가 통과한 다음 동일성 검토에서 기존 K와 비교한다.

최초 비교는 기존 hash/identity 검사를 재사용한다. 의미적 대조가 필요할 때만 작은 후보·기존 K 문맥으로 LLM 판단을 수행한다. 기존 K 전체와 모든 I 이미지를 매번 같은 호출에 반복 전달하는 것은 요구하지 않는다. 검색 결과나 embedding 유사도가 동일성 승인으로 바뀌지 않는다.

두 판정의 결과도 분리한다.

| 이번 후보와 기존 K | 이번 evidence | 반영 |
|---|---|---|
| 같은 의미 | 실제로 지지 | 같은 Revision에 검증된 grounding만 추가 |
| 같은 의미 | 부족·모호·반박됨 | 이번 grounding은 추가하지 않고 확인 필요로 남김 |
| 다른 의미 | 실제로 지지 | source/identity 규칙에 따라 별도 K 또는 정정 제안 |
| 기존 K의 내용 자체에 오류 발견 | 오류를 가리키는 근거 있음 | exact Revision 재검토 의무 생성; 새 후보의 기각과 구분 |

부분적으로 비슷한 후보의 근거를 더 넓은 기존 K의 근거로 추가해서는 안 된다. 재사용 대상의 실제 의미와 material conditions를 다시 비교하며, 관계가 entailment나 주제 관련성에 그치면 동일 의미로 처리하지 않는다. 근거 부족인 새 인용이 기존 K를 자동 무효화하는 것도 금지한다.

### 2. K 하나의 중요한 내용을 나눠 검증한다

한 K를 검사할 때 처치, 비교 대상, 관측 항목, 방향/수치, 시간·조건, 부정·불확실성·저자 귀속을 빠뜨리지 않는다. 값이 원문에 없으면 unknown/not reported로 남기며 '효과 없음'을 만들어 넣지 않는다.

예시 검증표의 각 행은 임시 Compiler Runtime 데이터이며 별도 I/K domain이 아니다. `support_checks` 같은 새 이름과 enum은 구현 시 frozen profile에 명시할 제안이다.

| 주장 요소 | 인용 refs | 판정 예시 |
|---|---|---|
| 처치 A에서 결과 X가 감소 | 실제 Data/I/block/char 범위 | 명시적 지지 |
| 처치 B에서도 결과 X가 감소 | 대응 인용 없음 | 근거 부족 |
| 보고되지 않은 Y에 효과가 없음 | Y의 측정·검정 없음 | 승인 불가 |

모델이 중요한 절을 검증표에서 누락하는 경우도 검사 대상이다. Validator는 생성된 문장과 구조화된 내용의 모든 material clause가 표에 포함됐는지 별도로 판정한다. 스크립트는 필수 entry/refs/판정의 존재는 강제할 수 있지만 의미적 완전성을 증명할 수는 없다.

표의 행 수만큼 K를 만드는 것은 아니다. 서로 다른 실험은 분리하되, 원문에 명시된 같은 대상의 결합 주장이나 의미상 함께 읽어야 하는 결과는 한 K로 유지할 수 있다. 자동으로 문자열을 쪼개 새 K를 만들지 않는다. 지지되지 않는 부분의 제거·분할은 LLM이 새 후보로 제안하고 다시 검증한다. I2K가 새 관계를 보충해서 통과시키지 않는다.

### 3. 인용을 직접 읽을 수 있게 제공한다

현재 block ID 검증은 유지한다. Validator에는 선택한 블록의 정확한 원문을 중복 제거한 evidence 목록으로 제공하고, 블록 앞뒤 문맥은 참고용으로 구별한다. 긴 quote를 hash만으로 표시하고 큰 I 본문에서 다시 찾아 읽게 하는 부담을 줄이는 시안이다.

참고 문맥에만 있는 내용은 자동으로 근거가 되지 않는다. 필요한 앞 블록을 찾았다면 exact ref를 명시적으로 추가한 뒤 재검증한다. 비연속 인용은 여러 범위를 그대로 저장하며 사이의 Figure caption 등을 삭제해 가짜 연속 quote를 만들지 않는다.

누락은 세 경우로 구분한다.

1. I에는 있으나 이번 인용에 빠짐: 기존 I의 정확한 범위를 추가 선택한다.
2. 이번 호출 밖의 I에 있음: 관련 I를 읽어 실제 전달 기록과 refs를 추가한다.
3. I에는 없고 등록 원본 D에만 있음: 승인된 직접 D 근거 경로로 원본을 확인하고 결손과 사용 위치를 기록한다. 이 경로의 실제 구현은 아직 필요하다.

어느 경우에도 D2I 재실행이나 I 내용의 사후 수정으로 해결하지 않는다. 원문에서 확인하지 못한 것은 보류한다. 원문 미지원 후보를 이름만 K2K로 바꿔 승인하는 우회도 허용하지 않는다.

### 4. 기존 K의 정정과 새 근거 추가를 구분한다

기존 [재검토 목록](../output/t04-multi-source/review-required.json)의 두 Revision을 우선 회귀 사례로 삼는다.

- 의미는 맞고 인용만 부족한 경우: 정확한 새 근거를 검증해 같은 Revision에 연결한다. 과거 근거의 상태 변화가 필요하면 append-only 검증 기록과 current support를 사용하며 과거 행을 덮어쓰지 않는다.
- 의미 범위가 잘못된 경우: exact current Revision을 기준으로 정정 제안을 검증한다. 같은 identity 안의 의미 수정이면 새 Revision, 별개 실험/identity로 나뉘어야 하면 그 규칙에 맞게 별도 K를 만든다. 단순히 모든 정정을 같은 Node의 다음 Revision으로 처리하지 않는다.
- 과거 오류와 정정 이유·원문·모델 판정을 보존한다. 연결된 Edge는 원래 endpoint를 바꾸지 않고 새 current 조합의 applicability를 재검증한다.
- 기존 K의 실제 사용 가능 상태를 변경하는 기능은 candidate rejection과 별도다. unresolved P의 public subtype/효력 enum을 이 설계 메모에서 승인된 것으로 취급하지 않는다. 실험 DB에서 구체 계약·영향을 검토한 뒤 필요한 승인 범위를 결정한다.

## 먼저 구현할 작은 단위

1. K 통합 요구를 다음 profile의 의무 목표에서 제거하고, 신규 Runtime 직접 호출에도 source-only 계약을 적용한다. 과거 request replay/저장된 profile은 보존한다.
2. 현재 두 오류를 모델에 답을 주지 않는 회귀 사례로 동결한다. clause별 support와 identity/evidence 분리의 schema·prompt·Runtime guard만 먼저 변경한다. 기존 `knowledge.py`, `multi_source_i2k.py`, `multi_source_prompts.py`, `knowledge_runtime.py`와 기존 tests를 확장한다.
3. 원문 그대로의 evidence 목록/앞뒤 문맥으로 실제 Generator·Validator를 재실험한다. 새 근거가 불충분한 reused 후보는 DB grounding 추가가 0이어야 한다.
4. 기존 K의 인용 보완과 의미 정정 경로를 구분해 구현한다. 수정 Revision·support 상태·Edge 재검증은 각각 영향에 맞게 처리한다.
5. 위 변경 뒤에도 중요 내용 누락이 반복될 때, 전체 I의 target 검토를 여러 입력 window로 배분하는 scheduler를 비교한다. target과 참고 I, 모든 target 범위/이미지의 검토 기록을 보존하고 D2I나 저장 I 수를 바꾸지 않는다. per-call context 조절을 전체 token/비용 cap에 의한 성공 종료로 바꾸지 않는다.

부수적인 확정 결함도 별도로 고친다. source 등록은 기존 grouped assembly의 정상 경로를 사용해 부모 canonical block I를 불필요하게 만들지 않는다. 모델 호출 전 설치된 runtime의 profile/prompt/schema와 worker request를 대조해 지난 host/container 버전 불일치를 호출 전에 차단한다. 기존 285개 I/실패 receipt/IDs는 임의 삭제·재작성하지 않는다.

## 검증 기준

- 알려진 처치군별 범위 확대를 승인하지 않고 올바른 처치군별 원문 주장은 승인한다.
- 유효한 block ID라도 핵심 절이 빠진 인용은 보류한다. 실제 앞 블록을 선택한 뒤 의미를 바꾸지 않고 근거를 보완할 수 있어야 한다.
- 기존 K와 같은 의미라는 판정만으로 새 evidence가 append되지 않는다. 새 인용의 실패가 기존 K를 자동 취소하지도 않는다.
- 원문 저자의 명시적 해석/가설은 귀속과 불확실성을 유지해 정리할 수 있다. 원문에 없는 결론·범위 확대는 I2K에서 막는다.
- 서로 다른 실험은 별도 source identity를 유지한다. 같은 의미의 검증된 재사용에는 새 semantic Revision을 만들지 않는다. multi-Data K 개수 목표는 없다.
- 선택된 전체 source I의 검토 의무와 미완료 이유가 보존된다. 검토 기록 100%와 중요 주장 회수율을 다른 수치로 보고한다.
- 모델 평가에는 올바른 후보/변조 후보, 모호한 후보, 기존 K 유무 조건, 처음 보는 다른 논문을 포함한다. 잘못 승인한 비율과 잘못 기각·보류한 비율, 인용 충분성, 알려진 중요 주장 누락을 함께 측정한다. 유한 평가에서 오류 0이 전체 원문 충실성을 증명하지는 않는다.
- 구조/PG 검사는 별도로 수행한다. 기존 source bytes·I·IDs·과거 Revision/FP 보존, 원자성, stale CAS, 재실행, 신규 경로의 우회 차단을 확인한다.

## 이번 검토에서 수행한 일

로컬 실험 보고서, 실제 판정과 code, identity/current-support 계약을 읽고 독립 코드 검토를 받았다. 이번에는 제안 문서만 추가했으며 앱 코드·DB·모델 호출·기존 실험 결과는 변경하지 않았다. 새 모델을 추가하거나 소형 LLM을 D2I에 넣는 것을 해결의 전제로 두지 않았다.

## 후속 LLM Wiki 참조

사용자의 추가 요청에 따라 [LLM Wiki 참조 조사](../output/t04-llm-wiki-references/REPORT.md)를 수행했다. source/page/index 운영 패턴, GraphRAG의 TextUnit 검색과 원문 backlink, Graphiti의 source/fact·시간 분리를 참고한다. I는 환각 대조용 원문 계층이면서 semantic search 대상이라는 요구를 유지한다. 외부 프로젝트의 자유로운 페이지 합성·이름 기반 병합·링크 추론·현재 파일 갱신을 그대로 I2K/identity/semantic Revision 계약으로 채택하지 않는다. K 통합이나 wiki 페이지와 KNode의 일대일 대응도 의무화하지 않는다. 후속 설계의 참고 자료이며 이 계획의 구현을 실행한 것은 아니다.
