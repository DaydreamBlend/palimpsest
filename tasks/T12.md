## 구현 순서

1. 45 invariant mapping을 구현된 tests와 연결하고 missing/skipped/xfail을 공개합니다.
2. PostgreSQL concurrent commit, worker crash, large graph streaming, backup restore, prompt injection/authority fixtures를 실행합니다.
3. 독립 gold set으로 D2I source fidelity, I2K/N2E/K2K correctness/materiality, retrieval/citation accuracy를 평가합니다. baseline과 candidate profile을 분리합니다.
4. 운영 데이터/비용/외부 전송을 쓰는 live eval은 허가된 범위만 수행하고 정확한 profile/dataset/version을 남깁니다.
5. release readiness, known limitations, rollback/runbook과 한 단계 demo command를 보고합니다.

## 변경 범위

hardening/tests/evals/runbook과 결함 수정 범위. failing test를 지우거나 threshold를 몰래 완화해 release green을 만들지 않습니다.

실제 code 경로는 T00 inventory의 module ownership map을 사용합니다. 제안 경로만 보고 기존 프로젝트를 재배치하지 않습니다. 새로운 production dependency는 기존 정책과 승인을 따릅니다.

## 현재 사용자 변경 — 이 task에 적용

U01–U03은 이미 적용된 요청이다. CLI-first/GUI-last, PDF parser=MinerU, Artifact Store/Canonical Store/Compiler Runtime을 유지한다. 이 task에서는 GUI를 만들지 않는다. P01–P12는 별도 승인 상태를 확인한다.

## 추가 release 조건

U01–U03과 AT82–AT105를 포함한다. GUI 없는 환경에서 PDF import→MinerU→validated I→K→query→explicit decision→trace→P/B export가 재현되어야 한다. 실제 MinerU/version/backend/출력 schema를 기록한다. GUI는 T13 deferred이며 CLI release의 선행 조건이 아니다. T12가 끝났다고 자동으로 T13을 시작하지 않는다.

U08 관련 추가 시나리오: AT106, AT107. [구조 해결 계약](../docs/decisions/ARCHITECTURE_FIXES.md)의 사용자 선택 상태를 확인하며 승인 전 정책을 임의 채택하지 않는다.

U09 관련 추가 시나리오: AT108, AT109, AT110, AT111, AT112. [저장 계약](../docs/decisions/STORAGE_IDENTITY.md)의 PostgreSQL/pgvector exact profile, SHA-256/UUIDv7, duplicate/retry/race, 도구 관리 등록·crash 복구, Runtime Record 보존·atomic 반영과 검색 profile 한도를 실제로 검증한다. [T02 SQL 초안](../docs/schema/T02_STORAGE_SCHEMA.md)과 문서 검증의 통과를 실제 PostgreSQL 적용·복구·모델 평가로 대체하지 않는다. PG19 이상을 release 대상으로 선택할 때에는 별도 사본에서 major/extension upgrade와 restore를 검증한다.
