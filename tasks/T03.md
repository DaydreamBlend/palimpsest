## 구현 순서

1. pin한 MinerU version/backend를 local worker adapter로 연결한다. requested/resolved config와 parser-profile identity, raw output/manifest hashes를 기록하고 no-silent-fallback을 유지한다.
2. raw blocks/text/type/structure, image/table/equation, original page/region/raw locator를 보존한다. 모든 요청 page와 source block을 coverage map으로 확인한다. Figure 전체/panel/caption/continuation을 대조하며 header/footer/reference text도 가치로 삭제하지 않는다.
3. `source-d2i-v1`의 결정적 normalization/assembly/구조 검사를 구현하고 `source-information-v1`의 source `unit_type`, `semantic_type=null`, source content와 exact refs를 만든다. D2I application LLM 호출은 0이다. context chunk·embedding/retrieval filter는 별도 projection으로 남긴다.
4. source-specific identity, operation claim/retry/partial/zero-output, 전체 coverage gate를 구현한다. 신규 opaque I/Record/execution은 UUIDv7이며 동시/retry의 canonical effects는 idempotent하다. I/grounding/provenance·Runtime terminal Record·candidate cleanup·outbox를 승인된 transaction에 반영한다.
5. 기존 semantic I/Record/provider receipt/ID/hash 및 설치 migration은 immutable history로 보존한다. 새 source schema는 additive migration으로 적용하며 자동 재분류·supersession을 하지 않는다. 명시적 repair 경로의 기존 support/provenance 규칙을 지킨다.
6. CLI compile data/jobs show/information show에서 source profile, page/block coverage와 flags, structural acceptance와 semantic approval의 차이, failure/partial/zero-output/blocked를 설명한다. unsupported/누락을 전체 성공으로 표시하지 않는다.
7. synthetic unit tests·실제 PostgreSQL atomicity/retry·실제 native PDF와 scanned/mixed PDF MinerU smoke·원문 QA를 별도 기록한다. 제공 PDF의 6개 전체 Figure와 source block coverage를 대조한다. 한 문서의 통과를 모든 PDF/OCR 품질 통과로 확대하지 않는다. 허가된 local 처리 범위만 사용한다.
