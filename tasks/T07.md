2026-09-14 T17 후속: [정확한 반복 결과 진단](../output/t17-propagation-anomaly/REPORT.md)을 앱0.17/schema0016에서 구현했다. 실제 전제·current support·버전·profile이 같은 A→B→A/A→B→C→A 및 Edge 적용성 복귀를 보류하고 exact witness 확인과 freshness 검사 후 재개한다. 2026-09-14 후속: [전파 worker](../docs/interfaces/PROPAGATION_WORKER.md)를 구현해 저장된 root/outbox/현재 support의 causal 후속 처리, 중단·재개·lease fence와 Wiki 재생성·독립 검증을 연결했다. [실제 결과](../output/t16-propagation/REPORT.md), [계획](../progress/T16_propagation_execplan.md)을 따른다. node-only 지원 범위의 실제 PostgreSQL/모델 동작을 검증하며 아래 전체 T07 acceptance를 일괄 완료하지 않는다. 128단계·100001 fanout, 의미 oscillation 탐지, EffectiveEdge 전제 추론은 여전히 별도다.

2026-09-13 상태: **IN_PROGRESS — node-only K2K·자료 버전 구현 및 실제 코드 실험**. [첫 Runtime](../docs/interfaces/K2K_RUNTIME.md), [당시 결과](../output/t11-codebase-k2k/REPORT.md)에 이어 [현재 자료 버전 실험](../progress/T07_versioned_code_execplan.md)에서 실제 Terra I2K/N2E/K2K를 검증한다. 전체 scheduler/quiescence acceptance는 계속 미완료다.

2026-09-11 사용자 명확화: [LLM Wiki의 K2K 지식 생성](../docs/decisions/LLM_WIKI_RETRIEVAL.md)에 따라 K는 귀납·연역으로 새 지식을 만드는 계층이다. I를 새로 만들거나 D2I를 재실행해 파생 결론의 근거를 꾸미지 않는다. 정확 전제 KRevision/EffectiveEdgeRef, 추론 유형·가정·한계·간결한 도출 근거와 Validator 결과, transitive I/D provenance를 유지한다. 기존 I2K slice의 direct I grounding 필수 제약을 모든 K2K에 그대로 적용하지 않는다.

K2K가 생성하는 것은 구조화된 후보이며 실제 관측·사용자 결정이 아니다. 같은 의미는 reuse/근거 추가이며, 전제 변화는 정확 dependency를 통한 재검증 대상이다. 과거 Revision을 덮어쓰지 않고 N2E의 의미 관계 생성과 Compiler Record의 도출 의존성을 구분한다. 실제 코드에서 제한된 연역 실행을 확인하더라도 일반적인 귀납/연역 품질이나 전체 자동 전파 완료를 뜻하지 않는다.

[최신 사용자 정정](../docs/decisions/I2K_SOURCE_ONLY_K2K_INFERENCE.md)에 따라 원문에 없는 새 결론·추측은 K2K만 생성한다. [다중 source I2K](../docs/decisions/MULTI_SOURCE_I2K.md)는 명시된 내용을 통합·정리하며 새 추론을 만들지 않는다. K2K로 새로 도출한 Revision의 필수 metadata는 실제 `origin_operation=k2k`, `is_inferred=true`, 검증된 `inference_type`, exact accepted KRevision/EffectiveEdge 전제와 추론·검증 Record다. 이 정보는 저장뿐 아니라 K 조회/답변에도 표시한다. 원문 직접 근거가 나중에 추가되어도 최초 추론 생성 기원을 변경하지 않는다. 기존 source-origin K를 같은 의미로 재사용할 때도 추가 K2K 근거만 append하고 최초 기원은 유지한다. 상세 [필수 기원 정보](../docs/decisions/LLM_WIKI_RETRIEVAL.md)를 따른다.

## 구현 순서

1. semantic work dedup, dependency paging, lease/retry/fan-in과 source watermark를 구현합니다.
2. K2K는 context-bounded input으로 호출하되 전체 propagation depth/size/cost cap을 두지 않습니다.
3. semantic impact와 maintenance events를 분리하고 no-material에서 새 branch를 생성하지 않습니다.
